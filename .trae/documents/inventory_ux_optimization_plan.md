# 交互修改与业务逻辑优化计划

## 1. 现状与目标分析

根据您的需求，系统将从“基于数量的库存管理”转变为“基于唯一实体（一物一码）的单据管理”，并在售出流程中引入“状态流转”概念。具体目标如下：

* **单据化管理**：每个价格单代表一个具体商品（数量恒定为 1）。历史数据中 `quantity > 1` 的记录将被自动拆分为多条。

* **状态流转**：新增状态管理：`待售 (for_sale)` -> `已售待使用 (sold_pending)` -> `已使用 (used)`。

* **拖拽排序**：支持在手机端通过长按拖拽调整单子的顺序。

* **组合售卖**：通过勾选具体的单据进行售卖，输入总售价，系统将这批售出绑定为一个批次（Batch）。

* **极简明细**：销售明细按“售出批次”展示，卡片折叠时只显示名称、售卖数量和总价格；展开后具体显示每个商品的单独价格和所属平台。

## 2. 数据库变更 (SQL 迁移)

在执行前端代码修改前，需要先在 Supabase 运行一段 SQL 脚本，用于兼容历史数据并新增必要字段。

**变更内容：**

1. `tickets` 表新增 `status` 字段（默认 `for_sale`）和 `sort_order` 字段。
2. 遍历 `tickets` 表，将 `quantity > 1` 的行自动拆分为多行 `quantity = 1` 的记录，以兼容单据化管理。
3. `sales` 表新增 `batch_id` (UUID) 字段，用于将一次组合售出的多张单据聚合在一起。
4. `sales` 表新增 `fee` (DECIMAL) 字段，用于记录每笔销售产生的 0.6% 手续费。

## 3. 前端改造详细方案

### A. 依赖安装

* 引入 `@dnd-kit/core`, `@dnd-kit/sortable`, `@dnd-kit/utilities` 以支持触控友好的长按拖拽排序。

### B. 库存页面 (`Tickets.tsx`)

* **移除商品折叠**：保留平台的折叠面板，但内部的商品列表改为平铺展示，移除商品的 Accordion。

* **添加价格单**：移除输入数量的字段，默认且强制只创建 1 个。

* **单据行重构**：

  * 左侧增加长按拖拽手柄（拖拽后自动更新 `sort_order`）。

  * 中间显示成本价和状态徽章（绿色 `待售`，橙色 `已售待使用`）。

  * 如果状态是 `已售待使用`，右侧显示「核销」按钮，点击后状态变为 `已使用`，并从当前列表中过滤隐藏。

  * 隐藏掉右侧的加减数量控制器。

### C. 数据看板与售卖弹窗 (`Dashboard.tsx`)

* **关于「核销按钮」位置的思考与设计**：
  * **分析**：看板是整个业务流转的中心。用户在看板完成“售出”动作（状态变为“已售待使用”）；如果在看板也能直接进行“核销”（状态变为“已使用”），用户处理订单的完整生命周期就不需要在“看板”和“库存”两个页面之间来回切换。而“库存”页面可以更纯粹地专注于“进货成本管理”和“列表排序”。
  * **结论**：**核销按钮更适合放在看板的全局商品详情页中**。同时，看板的详情列表也会展示每一单的状态。

* **全局商品详情优化**：
  * 列表不仅显示成本和平台，还额外显示该单据的当前状态徽章（`待售` 或 `已售待使用`）。
  * 针对 `已售待使用` 状态的单据，直接在右侧提供「核销」按钮，点击后变更为 `已使用` 状态并隐藏/归档。

* **勾选式组合售卖**：
  * 列出该商品下所有的单据，状态为 `待售` 的前方带有 Checkbox 允许勾选；状态为 `已售待使用` 的单据不允许被勾选。
  * 勾选完成后，在底部输入这批单据的「总售价」。

* **数据提交与手续费计算**：
  * 生成一个唯一的 `batch_id`。
  * 根据用户输入的总售价，计算出 **0.6% 的手续费**（`总售价 * 0.006`）。
  * 最终单据利润 = `售出价格 - 成本 - 手续费`。
  * 在 `sales` 表中插入多条记录，全部带上此 `batch_id`、手续费（`fee`）和扣除手续费后的最终利润。
  * 更新被勾选的 `tickets`，将其 `status` 改为 `sold_pending`。

### D. 销售明细页面 (`Sales.tsx`)
- **数据聚合**：在前端按 `batch_id`（对于历史数据按 `id`）对拉取到的 `sales` 数据进行 Group By 聚合。
- **极简卡片 UI**：
  - **默认折叠态**：显示 商品名称、售卖数量、总价格、售出时间。
  - **点击展开态**：显示包含的每个商品的单独价格（成本价、售出单价）、所属平台，以及**该商品当前的核销状态（待使用 / 已核销）**。底部展示该批次的**总成本**、**扣除的 0.6% 手续费**，以及**净利润**。
  - 提供整单「撤销」功能，撤销时通过 `batch_id` 删除销售记录，并将对应的 tickets 状态恢复为 `for_sale`。

## 4. 验证步骤

1. **数据库**：确认 Supabase SQL 执行成功，历史数量全部变为多条单据。
2. **库存交互**：测试新建价格单是否只有1个；测试长按拖拽是否能改变顺序并刷新保留；测试「核销」按钮是否生效。
3. **售出流程**：在看板勾选 3 个单子，输入总售价 100 元，确认售出。回到库存查看这 3 个单子是否变为“已售待使用”。
4. **明细聚合**：前往明细页，确认刚才的售出显示为一个统一的批次卡片，点击展开数据计算准确。
