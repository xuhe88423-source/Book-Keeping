# 各平台单据分布页面交互优化计划

## 1. 目标与背景
用户希望优化数据看板中点击商品卡片后弹出的“各平台单据分布页面”（商品详情弹窗），以提升跨平台售卖的操作效率。具体需求包括：
1. **固定底部操作栏**：将底部的“删除”和“跨平台组合售出”（现改为“售卖”）按钮固定在弹窗底部，不随商品列表内容滚动。
2. **合并售卖选择**：去掉单独的“组合售出”弹窗。直接在当前的“单据分布”列表中增加勾选框，允许用户直接在这里勾选需要售卖的单据。
3. **保持弹窗开启**：完成售卖操作后，不关闭当前弹窗，让用户留在该页面继续查看或进行其他操作。
4. **固定顶部标题**：弹窗顶部的商品名称和关闭按钮需固定，不随内容滚动。

## 2. 当前状态分析
目前 `Dashboard.tsx` 中：
- `isDetailOpen` 控制商品详情弹窗，列表是纯展示，底部有“删除”和“跨平台组合售出”按钮。弹窗整体使用 `overflow-y-auto`，导致头尾会跟随内容一起滚动。
- `isSellOpen` 控制独立的组合售出弹窗，包含勾选单据、输入售价、日期及确认售出按钮。
- `handleSellTicket` 成功后会调用 `setIsSellOpen(false)`。

## 3. 具体修改方案 (`src/pages/Dashboard.tsx`)

### 3.1 弹窗结构重构 (固定头尾)
修改 `isDetailOpen` 的 `<DialogContent>` 布局结构：
- **容器**：改为固定最大高度的 Flex 容器，隐藏外部滚动条 (`max-h-[90vh] flex flex-col p-0 overflow-hidden`)。
- **顶部 (Header)**：设为 `shrink-0 p-6 border-b`，包含商品名称与关闭按钮。
- **中间 (Body)**：设为 `flex-1 overflow-y-auto p-6`，包裹单据分布列表。
- **底部 (Footer)**：设为 `shrink-0 p-4 border-t bg-gray-50/80 backdrop-blur-md`，包含售价输入、日期选择以及“删除”和“售卖”按钮。

### 3.2 整合售卖功能到详情页
- 废弃原有的 `isSellOpen` 弹窗相关 JSX 代码。
- 在详情页的 Body 列表中，为每一个状态为 `for_sale` 的单据添加 Checkbox 勾选框（复用原售卖弹窗的逻辑）。
- 在详情页的 Footer 区域，加入“总售价”和“售出日期”的输入框（可设计为水平并排以节省空间），并在其下方放置圆形的“删除”按钮（左侧）和“售卖”按钮（右侧，占主导）。

### 3.3 修改售卖事件逻辑
在 `handleSellTicket` 中：
- 将售出成功后的 `setIsSellOpen(false)` 和关闭详情页的操作移除。
- 保留清空 `batchSellData`（重置金额和选中状态）并调用 `fetchDashboardData()` 刷新数据的逻辑，从而实现“停留在当前页面，且单据状态实时变为已售待使用”。

## 4. 验证步骤
1. 点击任意商品卡片，确认弹窗头部和底部是否固定，只有中间单据列表可滚动。
2. 确认单据列表中直接出现了复选框，可以直接勾选待售单据。
3. 在底部输入金额并点击“售卖”，确认单据成功变为“已售待使用”状态，同时弹窗未关闭，金额输入框和选中状态被重置。
