# 各平台单据分布页面极简网格视图优化计划

## 1. 目标与背景

为了解决用户在长列表中滑动寻找低价单据的痛点，且在**不改变单据自定义排序**的前提下，将“各平台单据分布”改造为**极简高密度网格视图**，并通过**颜色高亮**自动标出全场最低价。让用户一眼锁定最低价并快速完成勾选。

## 2. 核心设计方案 (`src/pages/Dashboard.tsx`)

### 2.1 提取全局最低价

在渲染弹窗前，遍历当前选中的商品 (`selectedProduct`) 下所有 `for_sale`（待售）状态的单据，计算出**全场最低成本价 (`lowestPrice`)**。

### 2.2 极简高密度网格布局 (Grid View)

* 将原本每个单据占据一整行的纵向列表 (`space-y-2`) 改为高密度的网格布局：`grid grid-cols-3 sm:grid-cols-4 gap-2`。

* 这样每行可以容纳 3 到 4 张票，大大缩短了列表的高度，减少滑动。

### 2.3 单据卡片视觉重构

单据将变成类似小按键的方形卡片，去掉冗余的文字说明，突出核心信息（价格与状态）：

* **默认待售票**：卡片居中大字显示 `¥ 价格`。

* **选中状态**：利用 Tailwind 的 `peer:checked` 机制，勾选后卡片边框加粗变为主色调 (Primary)，背景变为浅蓝色，右上角显示勾选图标 (Check)。

* **最低价高亮**：如果该票是 `for_sale` 且价格等于 `lowestPrice`，则默认赋予显眼的**红色或金色边框/背景**，并在卡片顶部附加极小的“最低”或“🔥”角标，通过色彩对比瞬间抓住眼球。

* **已售待使用票**：背景变为浅橙色 (`bg-orange-50`)，不可勾选。卡片内部直接放置一个明显的“核销”按钮（绿色 Check 图标），点击即可直接核销。

## 3. 具体修改步骤

1. 在 `Dashboard.tsx` 的详情弹窗渲染逻辑中，加入 `lowestPrice` 计算。
2. 定位到 `selectedProduct?.platformDetails.map` 内部渲染 `availableTickets` 的区域。
3. 更改父容器的 class 为 `grid grid-cols-3 sm:grid-cols-4 gap-2.5`。
4. 重写内部的 `<label>` 结构：

   * 隐藏原生的 `<input type="checkbox" className="peer sr-only" />`。

   * 使用 `peer-checked:ring-2 peer-checked:ring-primary ...` 来控制卡片的选中态 UI。

   * 根据 `ticket.status` 和 `ticket.cost_price === lowestPrice` 组合不同的 CSS 类名（高亮、灰态、橙态）。

   * 对于 `sold_pending` 状态的票，在卡片内部叠加绝对定位或相对布局的 `<button>` 以触发 `handleWriteOff` 核销操作。

## 4. 验证步骤

1. 打开任意包含多张票据的商品。
2. 确认单据是否已经变成紧凑排列的 3-4 列网格。
3. 确认所有待售单据中，价格最低的那些是否带有明显的颜色高亮（如红色边框/背景）。
4. 点击高亮或普通的待售单据，确认是否能正常选中并高亮变色。
5. 点击处于“已售待使用”单据上的“核销”按钮，确认功能是否依然正常运作。
