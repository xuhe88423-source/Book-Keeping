# 库存管理逻辑优化计划

## 1. 现状分析
当前库存页面的折叠面板（Accordion）表现为互斥展开（手风琴模式），只能同时展开一个平台或商品；且在库存页面中仍保留了商品的重命名和删除功能。而根据之前的重构，商品的创建已统一移至“看板（Dashboard）”页面。

## 2. 需求目标
- **取消互斥展开**：允许用户同时展开多个平台和商品面板，且继续保持状态记忆功能。
- **精简库存操作**：移除库存页面中针对“全局商品”的“重命名”和“删除”操作，仅保留添加优惠券（进货）功能。
- **商品统一管理**：在“看板”页面的“商品详情弹窗”中增加“删除商品”功能，点击删除后，同步级联删除各平台的关联数据。

## 3. 实施方案

### 3.1 优化折叠面板 (Accordion) 的多选模式
- **文件**: `src/pages/Tickets.tsx`
- **操作**: 找到渲染平台和渲染商品的 `<Accordion>` 标签，显式添加 `multiple` 属性。
- **说明**: 结合现有的 `value` 为 `string[]` 类型的状态，`multiple` 属性将激活 `@base-ui/react/accordion` 的多重展开模式。

### 3.2 移除库存页的商品管理按钮
- **文件**: `src/pages/Tickets.tsx`
- **操作**: 
  - 删除商品行右侧的“修改(Pencil)”和“删除(Trash2)”按钮。
  - 移除对应的状态变量 (`editProductType`) 以及对应的处理函数 (`handleEditProductType`)。
  - 删除页面底部的“修改商品名称”的 `Dialog` 弹窗。
  - 在 `handleDelete` 的 `deleteConfirm` 弹窗逻辑中，移除 `product_type` 的相关提示和判断。

### 3.3 看板页增加商品删除功能
- **文件**: `src/pages/Dashboard.tsx`
- **操作**:
  - 新增 `deleteConfirm` 状态用于控制删除商品的二次确认弹窗。
  - 新增 `handleDeleteProduct` 函数，调用 Supabase API 执行 `global_products` 的删除操作（依托于数据库现有的 `ON DELETE CASCADE` 机制，将自动删除所有关联的票据和销售记录）。
  - 在“商品详情弹窗 (isDetailOpen)”的 Header 区域（名称旁边）或者底部按钮旁，增加一个醒目的红色“删除商品”图标按钮。
  - 增加二次确认的 `Dialog`，告知用户删除的破坏性后果（会同步删除各个平台的票据及明细）。

## 4. 验证步骤
1. **展开测试**：在库存页面点击展开平台 A，再点击平台 B，确认 A 不会自动收起。刷新页面后，确认展开状态仍然保留。
2. **UI 确认**：进入库存页面，确认所有平台下的商品旁边，仅保留“总计”信息，不再有修改和删除按钮。
3. **删除测试**：回到看板页面，点击某个测试用的商品打开详情，点击“删除商品”按钮，同意二次确认。确认删除成功后，库存页对应的商品完全消失。
