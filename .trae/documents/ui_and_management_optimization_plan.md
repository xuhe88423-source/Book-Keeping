# 记账应用优化方案：管理功能增强与苹果风格 UI 重构

## 1. 概述 (Summary)
本项目旨在落实两个核心优化方向：
1. **方向一（容错与管理）**：为平台、商品、具体优惠券以及销售记录增加“编辑”与“删除”功能；增加“撤销售出”功能。
2. **UI 界面重构（Apple 风格）**：全面抛弃现有的基础样式，引入类似 iOS/macOS 的设计语言，包括大圆角、半透明毛玻璃效果、更柔和的阴影、系统级蓝/白/灰配色、以及分组列表 (Grouped List) 的卡片设计。

## 2. 现状分析 (Current State Analysis)
- **数据结构**：目前数据库（Supabase）的四张表已经配置了 `ON DELETE CASCADE`（级联删除）。这意味着如果直接删除平台，其下的所有商品、优惠券以及关联的**销售记录都会被一并删除**。
- **UI 现状**：目前使用了 shadcn/ui 的默认配置（偏向方正、细边框、企业级后台风格），在手机端显得不够精致，底部导航栏缺乏沉浸感。

## 3. 具体修改方案 (Proposed Changes)

### 3.1 容错与管理功能 (方向一)
**修改文件**：`src/pages/Tickets.tsx`, `src/pages/Sales.tsx`
- **编辑功能**：
  - 在“平台”、“商品类型”卡片头部增加“编辑”图标，点击可修改名称。
  - 在“具体优惠券”记录中增加“编辑”图标，允许修改成本价（不影响已售出的利润记录，但会影响之后售出的计算）。
- **删除功能 (带危险警告)**：
  - 在各层级增加“删除”按钮。由于级联删除的破坏性，点击删除时必须弹出红色的**“二次确认弹窗”**，明确告知用户“删除平台/商品会同时删除其下的所有库存和历史销售明细”。
- **撤销售出 (Undo Sale)**：
  - 在 `Sales.tsx`（销售明细）中，将原来的表格/列表项增加“撤销”按钮。
  - **逻辑**：点击撤销时，从 `sales` 表中删除该记录，并将 `sales.quantity` 加回到对应 `ticket_id` 的 `tickets.quantity` 中。

### 3.2 苹果风格 UI 重构
**修改文件**：`src/index.css`, `tailwind.config.js`, `src/components/Layout.tsx`, `src/pages/*.tsx`
- **色彩与基础设定**：
  - 修改 `index.css` 的 CSS 变量，将主色调 `--primary` 改为经典的 iOS 蓝色 (`#007AFF`)，背景色改为偏暖的浅灰 (`#F2F2F7`)，卡片背景纯白。
- **全局布局 (`Layout.tsx`)**：
  - **手机端底部导航**：改用 iOS 风格的毛玻璃效果 (`backdrop-blur-xl bg-white/80`)，移除上边框，图标更加圆润。
  - **页面间距**：加大页面的整体内边距，取消生硬的边框。
- **卡片与组件风格 (Tickets & Sales & Dashboard)**：
  - 将所有的方角 `rounded-lg` 改为 `rounded-2xl` 或 `rounded-3xl`。
  - 取消硬边框 `border`，改用极淡的阴影 `shadow-[0_2px_10px_rgba(0,0,0,0.04)]`。
  - **列表重构**：将 Accordion (手风琴) 和表格改为 iOS 设置页那样的**分组列表 (Grouped List)**，各项之间用细线分割，整个大组带圆角。
  - **按钮样式**：将默认的直角按钮改为胶囊形状 (`rounded-full`)。

## 4. 假设与决策 (Assumptions & Decisions)
- **级联删除决策**：采用现有的 `ON DELETE CASCADE` 机制，不改为软删除 (Soft Delete)，但通过前端强烈的二次确认来防止误删。
- **编辑成本价的影响**：修改库存的成本价，只会影响**未来的售出**利润计算，不会修改过去已经生成的 `sales` 记录里的利润（因为 `sales` 表已锁定了当笔利润）。
- **UI 组件兼容性**：保留现有的 Radix UI / shadcn 底层逻辑，只通过修改 className 和 CSS 变量来实现 Apple 风格的视觉覆盖，以保证功能稳定。

## 5. 验证步骤 (Verification steps)
1. **UI 验收**：在浏览器切换到手机调试模式，确认底部导航栏有毛玻璃效果，卡片有大圆角，整体配色像 iOS。
2. **编辑测试**：修改某个平台或商品的名称，确认页面和数据库同步更新。
3. **撤销测试**：在明细中“撤销”一笔售出，确认明细消失，且去“库存”页检查对应的券数量是否正确增加。
4. **删除测试**：点击删除平台，确认弹出严重警告；确认后，数据库对应的商品和明细均被清空。
