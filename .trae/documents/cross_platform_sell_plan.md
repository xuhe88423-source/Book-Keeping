# 跨平台组合售出 & 数据看板优化计划

## 1. 目标概述
- **跨平台组合售出**：支持一次性售出分布在不同平台但“商品名称相同”的票据，并统一输入一个总售价。
- **看板展示优化**：将数据看板顶部的“平台分布”改为“**商品全局聚合分布**”，不再按平台展示，而是按商品名称展示（包含所有平台的总库存）。
- **快捷售出入口**：点击看板上的商品卡片，会弹窗展示该商品在各个平台的具体库存分布细节，并提供一键进入“组合售出”的按钮。

## 2. 具体修改方案

### 2.1 改造数据看板 (Dashboard.tsx)
- **数据层**：修改 `fetchDashboardData`，将原来的 `platformStats` 替换为 `globalProducts`。
  - 遍历所有平台的数据，按 `product_type.name` 进行全局分组聚合。
  - 累加算出该商品的总库存量。
  - 保留其在各个平台下的详细票据数据（用于后续展示细节和售出）。
- **UI 呈现**：将原来的平台卡片替换为“商品聚合卡片”。
  - 显示商品名称和全局总张数。
- **点击交互 (弹窗 1：商品细节)**：
  - 点击商品卡片后，不再跳转页面，而是直接在当前页弹出一个 **商品细节 Dialog**。
  - 弹窗内按平台列出库存情况（例如：淘宝 - 2张，美团 - 1张）。
  - 弹窗底部提供一个醒目的【跨平台组合售出】按钮。
- **点击售出 (弹窗 2：批量售出)**：
  - 点击【售出】后，切换到售出表单。
  - 列出该商品下所有平台的可用票据，用户可以自由设定从“淘宝”出几张，从“美团”出几张。
  - 提供一个【总售价】输入框。
  - 提交时，计算平均单价，批量写入 `sales` 表并扣减各平台库存，最后刷新看板数据。

### 2.2 优化库存页面 (Tickets.tsx)
- **同步售出逻辑**：为了保持操作一致性，将 `Tickets.tsx` 中原有的单平台批量售出逻辑，也升级为“跨平台组合售出”。
  - 当在库存列表点击某个商品的“售出”时，同样会自动聚合其他平台同名商品的库存，弹出的售出界面与 Dashboard 保持一致。

## 3. 核心数据结构设计
```typescript
interface GlobalProduct {
  name: string;
  totalQuantity: number;
  platformDetails: {
    platformName: string;
    productTypeId: string;
    tickets: Ticket[];
  }[];
}
```

## 4. 实施步骤
1. **重构 Dashboard 数据聚合**：修改 `Dashboard.tsx` 的 SQL 查询与数据处理逻辑，生成 `globalProducts` 数组。
2. **构建 Dashboard 交互 UI**：实现商品卡片 -> 细节弹窗 -> 组合售出表单的嵌套 UI。
3. **实现跨平台售出提交逻辑**：处理表单提交，包含输入校验、单价计算、批量插入 `sales` 表和批量更新 `tickets` 表。
4. **同步更新 Tickets 页面**：复用或重写 `Tickets.tsx` 中的售出触发逻辑，使其同样支持同名商品的自动聚合。

## 5. 假设与确认
- **判断依据**：系统完全依赖**商品名称（Name）**是否绝对相等来进行跨平台聚合。
- **组件复用**：因为 Dashboard 和 Tickets 页面都需要相同的“跨平台批量售出”表单，可能会在两个文件里实现类似的逻辑，或者抽离公共逻辑（视代码复杂度而定，优先保证快速实现）。
