# 数据看板 (Dashboard) 优化与重构设计方案

## 1. 目标与背景 (Summary)
用户希望优化当前的 `Dashboard` 数据看板页面，主要包含两个诉求：
1. **精简顶部指标卡片**：将顶部四个核心数据指标卡片（今日利润、本月利润、总价值、总余量）的体积缩小，使界面更加紧凑。
2. **新增平台库存分布**：在看板中增加一个新模块，按“平台”分类展示各个平台当前的票据总余量。

## 2. 当前状态分析 (Current State)
- **UI 布局**：`src/pages/Dashboard.tsx` 中的四个指标卡片使用了较大的内边距（`p-6`）、较大的图标容器（`p-3.5`）以及超大号数值字体（`text-2xl`），导致在手机端占用过多高度。
- **数据结构**：目前的 `fetchDashboardData` 函数中，直接从 `tickets` 表拉取了所有票据用于计算总价值和总余量，并没有关联 `platforms` 表，缺乏按平台维度的聚合数据。

## 3. 设计与实现方案 (Proposed Changes)

### 3.1 顶部数据卡片 (Metric Cards) “瘦身”设计
- **缩减留白**：将卡片的内边距从 `p-6` 减小到 `p-4` 或 `p-3`。
- **缩小图标**：图标的背景容器变小，图标本身从 `w-6 h-6` 缩小至 `w-5 h-5`。
- **排版优化**：将原本的上下堆叠结构（图标在上，文字在下）改为**左右横向结构**（左侧图标，右侧文字和数值），这将极大地压缩卡片的高度，在手机端甚至可以一行展示两个卡片（`grid-cols-2`）而不显得拥挤。

### 3.2 页面整体布局 (Layout) 升级
为了合理放置新增的平台数据，我们将采用经典的**主次分栏设计**：
- **桌面端 (Desktop)**：使用网格布局（`lg:grid-cols-3`）。左侧占 2 列，保留宽大的“近 7 日利润趋势”柱状图；右侧占 1 列，放置全新的“平台库存分布”卡片。
- **移动端 (Mobile)**：保持上下流式堆叠，顶部为指标卡片 -> 利润图表 -> 平台库存分布。

### 3.3 新增“平台库存分布”模块设计
- **视觉呈现**：一个独立的毛玻璃质感卡片。
- **内容结构**：内部使用简洁的列表（List）形式展示。每一行左侧为平台名称（可配上小图标或颜色点），右侧为该平台当前所有的票据总数（加粗显示）。
- **数据流更新**：
  修改 `fetchDashboardData`，通过 Supabase 联合查询获取平台和票据信息：
  ```javascript
  const { data: platforms } = await supabase
    .from('platforms')
    .select(`name, product_types ( tickets ( quantity ) )`);
  ```
  在前端遍历累加每个 `platform` 下所有 `tickets` 的 `quantity`，最终生成 `[{ name: '淘宝', count: 15 }, ...]` 的数组，存入 `DashboardData` 状态中供组件渲染。

## 4. 执行步骤 (Implementation Steps)
1. **修改类型定义**：在 `Dashboard.tsx` 中扩展 `DashboardData` 接口，增加 `platformStats: { name: string; count: number }[]`。
2. **更新数据获取逻辑**：在 `fetchDashboardData` 中加入平台库存的连表查询和聚合计算代码。
3. **重构顶部卡片 UI**：修改 `statCards.map` 渲染部分的 Tailwind CSS 类名，实现横向紧凑布局。
4. **添加分布模块 UI**：在图表下方/右侧构建新的 `Card` 组件，通过 `map` 渲染 `platformStats` 列表。
