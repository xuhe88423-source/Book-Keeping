# 取消状态功能交互设计方案

## 1. 目标
在数据看板（Dashboard）的单据售卖弹窗中，允许用户取消已经设置的“待售”（active）和“预约”（reserved）状态，使其恢复到默认的无状态（for_sale）。

## 2. 交互方式设计 (基于用户确认)
采用 **Toggle (点击原按钮取消)** 的方式：
- 如果用户勾选了一批单据，点击“待售”：
  - 若这批单据中有部分或全部不是“待售”状态，则统一变为“待售”。
  - **若这批单据当前全部都已经是“待售”状态**，则判断为用户的意图是“取消待售”，将其统一恢复为默认的 `for_sale`（无状态）。
- “预约”按钮同理。

## 3. 具体修改步骤
- 修改 `Dashboard.tsx` 中的 `handleBatchUpdateStatus` 函数逻辑：
  1. 获取当前勾选的所有单据 ID (`selectedIds`)。
  2. 根据这些 ID 从 `selectedProduct.platformDetails` 中找出当前对应的所有 `tickets` 的状态。
  3. 检查是否**所有选中的单据**当前的 `status` 都已经等于目标操作的 `newStatus` (例如：点击了待售，且选中的单据目前全都是待售)。
  4. 如果是，则将这批单据的状态反转重置为 `for_sale`；如果不是，则统一修改为目标状态 (`active` / `reserved`)。

## 4. 验证标准
1. 选中一个“待售”单据，点击底部的“待售”按钮，单据恢复无状态。
2. 选中一个无状态的单据，点击底部的“待售”按钮，单据变为待售。
3. 同时选中一个无状态和一个“待售”的单据，点击“待售”按钮，两个单据都变为待售。
